# AI提名官开发工作流

## Phase 1: 需求确认

基于已确认的产品方案进行开发，核心页面：
1. 首页落地页（对外）
2. 登录注册（手机验证码）
3. 控制台首页
4. 新建项目
5. 关键词中心
6. 文章工作台
7. 多平台改写
8. 发布中心
9. 监控仪表盘

## Phase 2: 原子化交付

交付节奏：
1. 拆分功能为可独立交付的最小单元
2. 每个单元：编码 → 自测 → 验收 → git commit
3. commit message 描述 WHAT + WHY

质量门禁：
- 每个 commit 前必须通过类型检查（tsc --noEmit）
- UI 变更必须在浏览器中确认视觉效果
- 涉及 Supabase 的功能必须验证 RLS 策略

## Phase 3: 测试

测试范围：
- 主路径：注册 → 创建项目 → 生成关键词 → 写文章 → 改写 → 发布 → 监控
- 边界情况：空状态、极长文本、网络错误
- 响应式：至少检查 mobile 和 desktop 两个断点
- 数据隔离：确认用户只能看到自己的数据
